Professional Growth

Completing my Computer Science degree has helped me grow in ways that I did not really expect when I first started the program. When I began, I mostly thought of computer science as learning how to code and eventually becoming a software developer. As I moved through different courses, I realized there are so many different areas within computer science and that I do not have to fit into only one of them. I feel like this program helped me figure out what I am good at, what I enjoy, and what kind of work I could see myself doing in the future.

One of the biggest things I learned about myself is that I am very adaptable. Throughout the program, I worked with Java, C++, Python, JavaScript, SQL, HTML/CSS, React, Node.js, MongoDB, MySQL, SQLite, and several other technologies. There were plenty of times when I opened a new project or development environment and had no idea where to start. Over time, I became much more comfortable with that feeling. I learned that I do not need to know everything immediately. I feel confident in my ability to research a problem, break it into smaller pieces, test my code as I go, and continue working until I understand what is happening.

I also discovered that I really enjoy the combination of creativity and problem-solving that comes with computer science. UI/UX has become one of the areas that interests me the most because I like thinking about how an application looks and how someone will actually interact with it. At the same time, I also enjoy troubleshooting, testing, working with data, and figuring out why something is not working. I feel like those interests give me several possible directions for my career instead of making me feel like I have to choose one exact path immediately.

Collaboration and Communication

Another area where I feel I have grown is collaboration and communication. Computer science can sometimes seem like it is mostly about sitting behind a computer and writing code, but my coursework showed me that communication is a huge part of developing successful software. Developers need to understand what users and stakeholders need and then be able to explain technical decisions in a way that makes sense to them.

In The Gaming Room project, for example, I created a software design document based on the client's requirements for the Draw It or Lose It application. I had to think about what the client was asking for, compare possible solutions, and explain why certain choices would work better than others. I feel like projects like this helped me understand that being able to explain my reasoning can be just as important as being able to write the code.

Data Structures and Algorithms

My understanding of data structures and algorithms has also changed throughout the program. Before taking courses that focused on these areas, I mostly thought about whether my program worked. Now I understand that how a program reaches an answer matters too. In CS 300, I worked with vectors, hash tables, and binary search trees while creating a course-planning application. I had to think about how information was stored, searched, sorted, and retrieved. I feel like this helped change the way I approach programming because I now think more about efficiency and whether there might be a better way to solve a problem instead of stopping as soon as the program works.

Software Engineering

I feel like software engineering is probably one of the areas where I can see my growth the most. Throughout the program, I went from working with smaller pieces of code to developing applications with several different components working together. One example was Travlr Getaways, where I worked with MongoDB, Express, Angular, and Node.js to build a full-stack application. Projects like this taught me that an application is much more than what the user sees on the screen. There can be a database, APIs, business logic, authentication, and many other components working together behind the scenes.

I also became much more comfortable with testing and debugging. I have learned that I prefer testing things as I build them because it makes it easier for me to figure out where something went wrong instead of trying to debug an entire application at the end.

Database Development

I also found that I enjoy working with databases and data more than I expected. In DAD 220, I worked with MySQL and learned how to turn an ERD into relational tables, create primary and foreign keys, import information, join tables, and use SQL queries to analyze data. One of my projects involved analyzing product return information to look at things like returns by state and return percentages by product type.

I feel like this helped me understand that databases are not just places where an application saves information. How that information is organized can determine how useful it becomes later. Since then, I have also worked with MongoDB and SQLite, which has given me experience with different approaches to storing and managing data.

Security

Security is another area that changed the way I think about software development. In my secure coding coursework, including the Artemis Financial project, I learned that security should not be something that is only considered after an application is finished. I worked with identifying vulnerabilities and thinking about how development decisions could affect the security of an application. I feel like this gave me a better security mindset because now I understand that protecting user information and considering possible vulnerabilities should be part of the development process from the beginning.

Professional Goals

All of these experiences have also changed the way I think about my career. At the beginning of my degree, I thought I needed to graduate knowing exactly what type of developer I wanted to be. I do not feel that way anymore. I know that I enjoy UI/UX and software development, but I have also discovered that I enjoy testing, troubleshooting, application support, and working with data. I feel like my first position in technology is an opportunity to get my foot in the door, gain real-world experience, and continue discovering where my strengths fit best. My biggest goal is to find an opportunity where I can use what I have learned while continuing to grow.

Developing my ePortfolio has made that growth much easier for me to see. When I look back at projects I completed earlier in the program, I can see things that I would approach differently now. I feel like that is actually one of the best examples of how much I have learned. Instead of looking at older code and only seeing whether it works, I now notice things like organization, maintainability, efficiency, security, database design, testing, and user experience. I have become much more comfortable asking not only, "Does this work?" but also, "How could I make this better?"

ePortfolio Artifact Overview

The artifacts in my ePortfolio bring many of these skills together through my Watch The Weight Fall Off Android application, which I originally created in CS 360. I chose this application because I felt like it gave me a great opportunity to go back to something I created earlier in my degree and look at it with everything I know now. Instead of choosing three completely different projects, I decided to enhance the same application in three areas: software engineering and design, algorithms and data structures, and databases. I feel like this makes it easier to see how these different areas of computer science actually connect to one another.

For my Software Engineering and Design enhancement, I focused on improving both the organization of the application and the experience of the person using it. I added a circular progress indicator that shows the user's progress toward their weight goal, including their percentage completed and pounds remaining. I also separated the progress calculations into a WeightProgressCalculator class. I feel like this enhancement shows how much more I think about both the user experience and the organization of my code compared with when I originally created the application.

For my Algorithms and Data Structures enhancement, I wanted the application to do more with the information it was already collecting. I added functionality to sort weight entries by date, calculate average weekly weight change, and estimate how many weeks it may take the user to reach their goal. I also had to solve problems with the data itself when certain entries affected the accuracy of the calculations. I feel like this enhancement demonstrates how I learned to use algorithms to turn stored information into something that is actually useful to the user.

My Database Development enhancement focused on improving the application's SQLite database and adding milestone functionality. I added a way to store the user's starting weight and track five-pound milestones. Once a milestone has been reached, the application stores it so that the same milestone is not repeatedly shown. I also created a custom milestone popup so the database functionality connects directly to something the user can see and interact with. I feel like this enhancement helped demonstrate how closely databases, application logic, and UI can work together.

When I look at all three enhancements together, I feel like they tell the story of my growth throughout the Computer Science program better than any one project could by itself. The software engineering enhancement focuses on organization and user experience, the algorithms enhancement shows how I can analyze information and solve problems, and the database enhancement demonstrates how I can organize, store, retrieve, and use data. My code review shows where the application started and the areas I identified for improvement, while my narratives explain the challenges I faced and what I learned while completing each enhancement.

Overall, I feel much more prepared to enter the computer science field than I did when I started this program. I know I still have plenty to learn, and I actually think that is one of the things I enjoy about technology. There will always be another language, tool, framework, or problem to figure out. I feel like my biggest accomplishment from this program is not simply learning how to write code. I learned how to approach problems, how to keep going when something does not work the first time, how to evaluate my own work, and how to continue improving it. Those are skills I feel confident taking with me into my first professional technology role.
